# Checklist — 01: VCS Fundamentals & Git Origin

Track your mastery of Version Control System architecture and Git history.

---

### Conceptual Understanding
- [ ] Understand why manual versioning (`quiz-app-1`, `final`, `final-final`) fails in team environments.
- [ ] Explain what a Version Control System (VCS) is and its core benefits.
- [ ] Distinguish between Local VCS, Centralized VCS (CVCS), and Distributed VCS (DVCS).
- [ ] Name real-world examples for each VCS type (e.g., RCS for Local; SVN/CVS for CVCS; Git/Mercurial for DVCS).
- [ ] Identify the Single Point of Failure (SPOF) risks in CVCS.
- [ ] Explain why DVCS enables full offline development (committing, branching, diffing).
- [ ] Understand the historical origin of Git in 2005 (Linux kernel, BitKeeper dispute, Linus Torvalds).
- [ ] Explain the design goals of Git (speed, distributed architecture, snapshot-based storage, branching efficiency).

---

### Interview Verification Questions
- [ ] Can you explain why Git stores snapshots rather than file diffs?
- [ ] Can you answer: "Why is Git considered distributed when most companies use GitHub as a central server?"
- [ ] Can you articulate the trade-offs between SVN and Git in an interview?
